这个工具需要两套登录，各管一件事，都要配一次：
① OAuth 登录——走 Google 官方接口，用来查站点列表和查收录状态。
② 浏览器登录——Google 没有开放"请求编入索引"的接口，只能自动操作网页点按钮，所以需要一份真实的浏览器登录。

① OAuth 登录 查询用

以你本人身份调用官方接口。你这个 Google 账号名下的全部 GSC 属性自动可用， 不需要在任何站点里添加权限。

把 OAuth 客户端 JSON 拖到这里 在 GCP「API 和服务 → 凭据 → 创建凭据 → OAuth 客户端 ID」，类型选「桌面应用」
已在新标签页打开 Google 授权页，完成后这里会自动刷新…

回调地址 http://127.0.0.1:8765/oauth/callback —— 客户端类型选「桌面应用」就自动接受，不用手工登记。

务必把 GCP 的「OAuth 同意屏幕 / Google Auth Platform」发布状态改成「正式版」。 停在「测试中」的话授权令牌只有 7 天有效期。个人使用不需要提交审核。

② 浏览器登录 申请收录用

点下面的按钮会打开你本机真实的 Chrome，请在里面用自己的 Google 账号登录。 工具不经手你的密码，也不会替你点登录相关的任何按钮。

这条路跟官方 API 性质不同：它是自动操作 GSC 网页，属于灰色地带， 依赖 Google 页面结构、对方改版就会失效；遇到验证码会立即整体停止，绝不尝试绕过。 登录数据存在 accounts/browser_profile/，拿到它基本等于拿到你已登录的账号，别打包外传。

拉取流量数据

两边的 Google 接口都只支持按维度筛选、不支持按指标筛选——没法直接跟 Google 要 "点击量大于 1000 的站点"。所以要先逐站点把总量拉下来缓存，之后筛选就是瞬时的、 阈值随便改。GSC 数据有 2~3 天延迟，窗口已自动前移。

关于这个工具能做什么

能便宜地做的：用官方 URL Inspection 接口批量查收录状态，每个凭据每天 2000 次， 几千个 URL 随便扫。这是这个工具最扎实的价值——帮你从一堆页面里精准找出哪些还没被收录。

稀缺的：真正让 Google 优先抓取，只能靠自动点 GSC 网页上的「请求编入索引」， Google 没开放这个接口，而且每天名额很少（真实上限未公开）。

做不到的：没有任何官方 API 能"一键批量提交收录"。之前用的 Indexing API 已从本工具移除 ——官方只声明它支持 JobPosting / BroadcastEvent，普通网页调用虽然返回成功但对收录没有可靠作用。

所以正确的用法是：扫全站找出未收录的 → 存进待办池 → 每天挑最重要的一两条去申请。
