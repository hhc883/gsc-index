配置步骤备忘

两条路都从同一件事开始：建 GCP 项目并启用两个 API。

  1. 在 Google Cloud 控制台 新建项目
  2. 启用 Indexing API 和 Google Search Console API（两个都要）

路线 A：OAuth 登录（站点多、都在你自己账号下）

  1. 「API 和服务 → OAuth 同意屏幕」配置好，发布状态改成 正式版
  2. 「凭据 → 创建凭据 → OAuth 客户端 ID」，类型选 桌面应用，下载 JSON
  3. 把 JSON 拖到本页最上面的框，点「开始授权」，用你自己的 Google 账号同意
  4. 完事。GSC 那边什么都不用改
  5. 要更多配额：另开一个 GCP 项目重复 2~6 步，同一个邮箱再授权一次

路线 B：服务账号（代管他人站点 / 无人值守）

  1. 「IAM 和管理 → 服务账号」新建服务账号，生成 JSON 密钥并下载
  2. 在 Search Console 里， 逐个属性把服务账号邮箱添加为所有者（「完全」权限不够）
  3. 把下载的 JSON 拖到「服务账号密钥」的框里
  4. 要更多配额：另开 GCP 项目重复 3~5 步

关于配额与效果

Indexing API 官方文档只声明支持 JobPosting 与 BroadcastEvent 两类结构化数据。 普通页面调用会返回成功，但 Google 是否真的据此抓取并不保证——本工具把它当作加速手段， 而不是保证收录的开关。真正稳的路子仍然是站点地图 + 站内链接 + 内容质量。

每日配额按太平洋时间零点重置，本工具的记账口径与之对齐。
