# GSC 索引提交器

批量把网页 URL 推送给 Google 索引的本地工具，带网页操作界面。

双击 **`启动.bat`** 即可运行，浏览器自动打开 `http://127.0.0.1:8765`。

---

## 一、先看清楚它能做什么、不能做什么

这决定你对它的预期是否合理，请务必读完。

| 通道 | 作用 | 配额 | 说明 |
|---|---|---|---|
| **Indexing API** | 秒级通知 Google 抓取某个 URL | 200 条/天/GCP 项目 | Google 官方文档**只声明支持** `JobPosting` 和 `BroadcastEvent` 两类结构化数据。普通页面调用会返回成功，但 Google **不保证**据此抓取 |
| **URL Inspection API** | 查询 URL 当前的收录状态 | 2000 次/天/账号 | 完全合规，只读 |
| **Sitemap 提交 API** | 把站点地图提交给 GSC | 无实际限制 | 完全合规，Google 官方推荐路径 |

**一句话结论**：普通网站没有 100% 官方支持的"快速收录"接口。本工具把 Indexing API 当作**加速手段**，不是保证收录的开关。真正稳的路子仍然是站点地图 + 站内链接 + 内容质量。

工具做了三件让它比手工快得多的事：

1. **批量提交** —— 用 `batch` 接口一次请求打包 100 个 URL，200 条配额只需 2 次网络往返
2. **先查后交** —— 预检配额（2000）比提交配额（200）便宜 10 倍，先查一遍把已收录的筛掉，把宝贵的提交配额全用在真正没进索引的页面上
3. **多账号轮转** —— 配额按 GCP 项目计算，多配几个项目的凭据就能线性扩容，工具自动分派并记账，且只会把配额分给真正对目标站点有权限的凭据

## 二、快速开始

### 第 1 步：安装 Python

如果电脑没装过，去 <https://www.python.org/downloads/> 下载 3.10 或更高版本。
安装时**务必勾选 `Add Python to PATH`**。

### 第 2 步：双击 `启动.bat`

首次运行会自动创建虚拟环境并安装依赖，需要一两分钟。之后每次启动都是秒开。

装依赖卡住的话（国内网络常见），在项目目录开个命令行换国内源：

```bash
.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 第 3 步：配置认证（只需做一次）

见下一节。有两条路可选，站点多且都是你自己的就走 OAuth。配好之前，工具只能看不能用。

## 三、配置认证（两条路，选一条）

### 先决定走哪条

| | 路线 A：OAuth 登录 | 路线 B：服务账号 |
|---|---|---|
| 适用 | 站点都在**你自己**的 Google 账号名下 | 代管他人站点，或要做无人值守的服务端任务 |
| 每个站点加邮箱 | **不需要** | 需要，逐个属性加 |
| 污染站点权限列表 | 不会 | 每个站多一条记录 |
| 新增站点 | 自动可用，零操作 | 还要再加一次 |
| 额外注意 | 同意屏幕要设为「正式版」 | 权限级别必须是「所有者」 |

**有 10 个以上站点、且都是你自己的 → 走 A。** 两条路可以混用，配额分别计算。

### 通用第一步：建 GCP 项目并启用 API

1. 打开 <https://console.cloud.google.com/>，新建一个项目（名字随便起）
2. 在搜索框搜 **Indexing API**，进去点「启用」
3. 再搜 **Google Search Console API**，同样点「启用」

> 两个 API 都要启用。只启用一个的话，工具会在「账号管理」页明确告诉你缺哪个。

---

### 路线 A：OAuth 登录

**A1. 配置 OAuth 同意屏幕**（Google Cloud 里现在叫「Google Auth Platform」）

「API 和服务 → Google Auth Platform → 目标对象」，用户类型选「外部」，
「品牌塑造」里填好应用名和联系邮箱。

> ⚠️ **发布状态一定要改成「正式版 / In production」。**
> 停在「测试中」的话，授权令牌只有 **7 天**有效期，你得每周重新授权一次。
> 个人使用**不需要**提交 Google 审核 —— 改成正式版后，首次授权会出现一个
> 「未验证的应用」警告页，点「高级 → 继续前往」即可，之后不再出现。

**A2. 创建 OAuth 客户端**

「Google Auth Platform → 客户端 → 创建客户端」，应用类型选 **桌面应用**，创建后下载它的 JSON。

> 类型必须是**桌面应用**。桌面应用自动接受本机回调地址，不用手工登记；
> 建成「网页应用」的话，得把 `http://127.0.0.1:8765/oauth/callback` 加进它的
> 「已获授权的重定向 URI」里才行。

**A3. 授权**

打开工具 →「账号管理」→ 把 JSON 拖到最上面的框 → 点「开始授权」→
在弹出的 Google 页面用**你自己的账号**登录并同意。

回到工具就能看到「已连接 你的邮箱」。**Search Console 那边一个字都不用改**，
你名下的全部属性立刻可用。

---

### 路线 B：服务账号

**B1. 创建服务账号并下载密钥**

1. 左侧菜单 →「IAM 和管理」→「服务账号」→「创建服务账号」
2. 名字随便填，角色可以不选，直接创建
3. 建好后点进去 →「密钥」标签 →「添加密钥」→「创建新密钥」→ 选 **JSON** → 下载

JSON 里有个 `client_email` 字段，形如 `xxx@你的项目名.iam.gserviceaccount.com`，下一步要用。

**B2. 在 Search Console 里逐个属性授权**

1. 打开 <https://search.google.com/search-console>
2. 选中站点属性 →「设置」→「用户和权限」→「添加用户」
3. 粘贴上一步的 `client_email`
4. 权限一定要选 **「所有者」**

> ⚠️ 权限必须是**所有者**。选「完全」不够，Indexing API 会返回
> `Permission denied. Failed to verify the URL ownership.`
> 而且这一步**每个属性都要做一遍** —— 嫌麻烦就走路线 A。

**B3. 把密钥拖进工具**

「账号管理」→ 拖到「服务账号密钥」的框 → 点「验证全部凭据权限」。
看到绿色的「正常 · 所有者」就成功了。

---

### 想要更多配额？

配额按 **GCP 项目**算，不按站点算，也不看你用哪种认证方式。

- 路线 A：另开一个 GCP 项目，重复「通用第一步」+ A1/A2，用**同一个邮箱**再授权一次
- 路线 B：另开一个 GCP 项目，重复 B1~B3

每加一个项目就多 200 条/天。工具自动在多个凭据间分派任务并分别记账，
并且只会把配额分给**真正对目标站点有权限**的凭据——没权限的凭据即使还有配额剩余也不会被派活。

## 四、界面说明

### 提交索引

三种方式喂 URL，默认打开的是「站点地图抓取」：

- **站点地图抓取**：填地址后点「抓取 URL」，自动识别 sitemap index 嵌套和 `.gz` 压缩，最多递归 3 层、60 个文件。选好顶部的站点后，地址会**自动填成 `{站点}/sitemap.xml`**；如果实际地址不是这个规律，直接改输入框就行，改过的内容不会被切换站点冲掉。
- **粘贴列表**：每行一个 URL，`#` 开头的行当注释忽略。
- **上传文件**：拖 `.txt` 文件进去，同样每行一个 URL。

点「分析」后会得到一张表，把 URL 分成几类：

| 状态 | 含义 | 默认是否提交 |
|---|---|---|
| 待提交 | 预检确认没收录 | ✅ |
| 已收录 | Google 已索引，交了也是浪费配额 | ❌ |
| 近期已提交 | N 天内交过（默认 14 天，可在设置里改） | ❌ |
| 不属于本站点 | 域名和所选 GSC 属性对不上，交了必失败 | ❌ 且不可选 |

确认勾选后再点提交。提交过程有实时进度条和逐条日志。

「跳过分析，直接提交」适合你很确定这批 URL 都没收录的场景，会省掉预检的等待时间。

### 账号管理

两种认证方式都在这一页：最上面是「用我的 Google 账号登录」（OAuth），下面是「服务账号密钥」。

「账号列表」里会标出每条凭据的类型，并列出它**实际能访问的全部 GSC 属性**及权限级别，
当前选中的属性用 ▸ 标出。排查权限问题只看这一列就够了 ——
对不上说明凭据没被授权到这个属性，级别不是「所有者」说明权限不够。

### 收录查询

只查不提交，用来盘点站点的收录情况。消耗的是预检配额（2000/天），
和提交配额互不影响。结果可导出 CSV。

### 历史统计

累计提交量、收录率、最近 14 天趋势图、失败原因分布，以及可搜索的完整操作日志。

### 设置

并发数、批量大小、重复提交保护天数等都能调。改完点保存立即生效（改端口需重启）。

## 五、命令行用法

界面之外还留了 CLI，方便挂 Windows 计划任务做定时提交。

```bash
.venv\Scripts\python.exe gsc.py check
```

```bash
.venv\Scripts\python.exe gsc.py submit --file urls.txt
```

```bash
.venv\Scripts\python.exe gsc.py submit --sitemap https://example.com/sitemap.xml --limit 100
```

```bash
.venv\Scripts\python.exe gsc.py inspect --file urls.txt
```

```bash
.venv\Scripts\python.exe gsc.py stats
```

常用参数：`--dry-run` 只演算不发请求、`--no-inspect` 跳过预检、
`--force` 忽略重复保护、`--limit N` 限制本次条数、`--site` 临时指定站点。

## 七、常见问题

**Q：提示 `Permission denied. Failed to verify the URL ownership.`**
这是 Indexing API 的报错，说明凭据不是该属性的「所有者」。回到第三节重新加一遍权限，
权限级别必须选「所有者」，改完等一两分钟再试。

**Q：提示 `User does not have sufficient permission for site 'https://xxx/'`**
这是 Search Console API 的报错（预检、站点地图那条链路），两种原因：

1. **凭据根本没被加到这个属性上。** GSC 权限是**按属性逐个授予**的，而且
   「域名属性」`sc-domain:example.com` 和「网址前缀属性」`https://example.com/`
   在 GSC 里是**两个互不相通的属性**——给其中一个加了所有者，另一个依然是零权限。
   这是这条报错最常见的原因。
2. **加了，但级别是「完全」或「受限」。** 提交索引要求「所有者」，
   收录预检要求「所有者」或「完全」，「受限」两个都不行。

打开「账号管理」页，「可见的 GSC 属性」一列会列出这个凭据实际能访问的全部属性及权限级别，
对不上就是第 1 种，级别不对就是第 2 种。选中不可访问的属性时，「提交索引」页顶部也会直接弹红条提示。

**Q：多个凭据（账号）时，提交失败会不会连累整批？**
不会。提交前会先核实每个凭据对**当前站点**的真实权限，只把配额分给验证通过的凭据；
一个都没有就直接报错并列出每个凭据具体卡在哪一步，不会出现"某个无权限的账号偷偷把整批都试失败了"的情况。

**Q：提示某个 API 未启用**
报错信息里会带一个链接，点开直接启用即可。启用后等 1~2 分钟生效。

**Q：提示 `Google 端找不到这个服务账号`**
密钥对应的服务账号已在 GCP 控制台被删除，或密钥文件被改动过。重新生成一份。

**Q：配额什么时候重置？**
太平洋时间零点，约等于北京时间下午 3~4 点（受夏令时影响）。
工具的记账口径与 Google 一致。

**Q：提交成功了（日志显示 200），但去 GSC 网站看 URL 检查工具，怎么还是显示"申请编入索引"，没有"已申请"之类的状态？**
这是正常现象，不代表提交失败。**Indexing API 和 GSC 网站里那个手动按钮是两套完全独立的系统**：
Indexing API 只是给 Google 发一条"这个网址有更新"的通知，Google 服务器返回 200 只代表**收到了**这条通知；
GSC 网站上"申请编入索引"这个按钮则是一条独立的手动请求队列，它的界面状态和 Indexing API 有没有提交过毫无关系——
不管你之前是用工具提交过、还是在网页上手动点过，这个按钮**永远显示成可以点击的样子**，Google 没有在界面上做"已申请过"这种状态区分。

真正反映收录进展的是按钮上方的"网址状态"（网址未收录 / 已抓取未编入索引 / 已编入索引），
这个状态本身更新就要几小时到几周不等，跟你用哪种方式提交无关。想确认工具这边到底有没有交上去，
看「历史统计」页的日志：状态码 200 就是 Google 已确认收到，非 200 才是真的失败。

**Q：提交了为什么还没收录？**
如前所述，Indexing API 对普通页面不保证效果。它只是"告诉 Google 这里有更新"，
Google 抓不抓、收不收录，取决于页面质量、站点权重、内部链接等因素。
建议配合站点地图提交一起用，并用「收录查询」持续观察实际效果。

**Q：一次能提交多少？**
每个凭据每天 200 条。配了 3 个就是 600 条/天。
超出配额的部分工具会明确告诉你还剩多少、哪些没提交成功。

**Q：管理多个网站，每个都要在 GSC 里加一次邮箱吗？**
用**服务账号**的话是的，而且 Search Console API 没有管理权限的接口，只能在网页界面手动点。

**用 OAuth 登录就完全不用。** 站点都在同一个 Google 账号名下的话，
就以你本人身份授权（配置见第三节路线 A），GSC 权限列表一个字都不用改，
新增站点也自动可用。这是多站点场景的正确做法。

不管走哪条路，**配额都是共享的**：200 条/天按 GCP 项目算，不按站点算。
20 个站共用一个项目，就是这 20 个站一起分 200 条，摊下来每站每天 10 条。
要提量必须新建 GCP 项目。

**另外一个省事技巧**：同一域名下的多个属性，改用**域名属性**
`sc-domain:example.com` 替代前缀属性，一个属性即可覆盖 `http`/`https`/`www`/全部子域名。

**Q：OAuth 授权老是掉线，要反复重新授权？**
GCP 的「Google Auth Platform」还停在「测试中」状态。这种状态下 refresh token 只有 7 天有效期。
把发布状态改成「正式版 / In production」就好了，个人使用不需要提交审核。

**Q：同一批 URL 反复提交有用吗？**
没用，还烧配额。工具默认 14 天内不重复提交同一个 URL，这个天数可以在设置里调。

## 八、技术栈

后端 Python（FastAPI + uvicorn + google-auth + requests），前端是零依赖的单文件 HTML/CSS/JS，
本地数据用 SQLite。没有任何数据会发到除 Google 官方 API 以外的第三方服务器。
