# GSC 收录助手

批量查出网站有哪些页面没被 Google 收录，再逐个去 Search Console 申请收录。本地网页界面。

双击 **`启动.bat`** 即可运行，浏览器自动打开 `http://127.0.0.1:8765`。

---

## 一、先认清这个工具能做什么、不能做什么

这一节决定你对它的预期是否合理，请务必读完。

| | 能力 | 配额 | 性质 |
|---|---|---|---|
| **查收录状态** | 批量查每个 URL 有没有被 Google 收录 | 2000 次/天/凭据，**充裕** | 官方 URL Inspection API，完全合规 |
| **申请收录** | 让 Google 优先抓取某个 URL | 每站每天很少，**稀缺** | 自动操作 GSC 网页点按钮，**灰色地带** |
| **提交站点地图** | 告诉 Google 你的完整页面清单 | 无实际限制 | 官方 API，Google 推荐路径 |
| **看 GSC 流量** | 展现量、点击量、平均排名、搜索词 | 宽松 | 官方 Search Analytics API，**零配置**（复用现有 OAuth） |
| **看 GA 流量** | 会话数、用户数、浏览量、事件数、跳出率 | 20 万次/天/属性，充裕 | 官方 GA4 Data API，需重新授权一次 |
| **看此刻在线** | 最近 30 分钟的活跃用户及正在看的页面 | 同上 | 官方 GA4 实时报表，**GSC 完全给不了** |

**没有任何官方 API 能"一键批量提交收录"。** 这一点很重要：

- 早期版本用过 Google 的 **Indexing API**，但官方只声明它支持 `JobPosting`（招聘）和
  `BroadcastEvent`（直播）两类结构化数据。普通博客/产品页调用会返回 200 成功，
  但 Google **不保证据此抓取**——实测下来对收录没有可靠作用，所以**已从本工具移除**。
- GSC 网页上那个「请求编入索引」按钮是真的有效，但 Google **从未把它开放成 API**。
  本工具只能自动化操作网页去点它，这条路属于灰色地带、依赖 Google 页面结构、随时可能失效。

**所以这个工具的正确用法是：**

> 用便宜的查询配额扫全站，**精准找出哪些页面还没被收录**，
> 存成链接清单，每天挑最重要的一两条去申请，过几天再复查收录了没。

它的价值在于**帮你把稀缺的申请名额花在最值得的页面上**，而不是"能提交更多"。

## 二、快速开始

### 第 1 步：安装 Python 和 Chrome

- Python 3.10+：<https://www.python.org/downloads/>，安装时**务必勾选 `Add Python to PATH`**
- **Chrome**（或 Edge）：申请收录那一步需要调用你本机真实的浏览器。
  Playwright 自带的 Chromium 会被 Google 判定为"此浏览器或应用可能不安全"而拒绝登录。

### 第 2 步：双击 `启动.bat`

首次运行会自动创建虚拟环境并安装依赖，需要几分钟。之后每次启动都是秒开。

装依赖卡住的话（国内网络常见），在项目目录开个命令行换国内源：

```bash
.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 第 3 步：配两套登录

工具需要**两套登录，各管一件事，都要配一次**：

| | 用途 | 怎么配 |
|---|---|---|
| ① **OAuth 登录** | 查站点列表、查收录状态（官方 API） | 见下一节 |
| ② **浏览器登录** | 点网页上的「请求编入索引」 | 界面上点一下，用你自己账号登录一次 |

## 三、配置 OAuth 登录

### 1. 建 GCP 项目并启用 API

1. 打开 <https://console.cloud.google.com/>，新建一个项目
2. 搜索并启用 **Google Search Console API**

> 只需要这一个 API。早期版本还要启用 Indexing API，现在不需要了。

### 2. 配置同意屏幕

「API 和服务 → OAuth 同意屏幕 / Google Auth Platform」，用户类型选「外部」，填好应用名和联系邮箱。

> ⚠️ **发布状态一定要改成「正式版 / In production」。**
> 停在「测试中」的话授权令牌只有 **7 天**有效期，你得每周重新授权一次。
> 个人使用**不需要**提交 Google 审核——改成正式版后，首次授权会出现
> 「未验证的应用」警告页，点「高级 → 继续前往」即可。

### 3. 创建 OAuth 客户端

「凭据 → 创建凭据 → OAuth 客户端 ID」，应用类型选 **桌面应用**，下载它的 JSON。

> 类型必须是**桌面应用**。桌面应用自动接受本机回调地址，不用手工登记；
> 建成「网页应用」的话，得把 `http://127.0.0.1:8765/oauth/callback`
> 加进它的「已获授权的重定向 URI」里。

### 4. 授权

工具 →「账号管理」→ 把 JSON 拖到第①节的框 → 点「开始授权」→
在弹出的 Google 页面用**你自己的账号**登录并同意。

**Search Console 那边一个字都不用改**，你名下的全部属性立刻可用。

### 5. 浏览器登录

同一页第②节，点「开始浏览器登录」，会打开**你本机真实的 Chrome**，
在里面用自己的 Google 账号登录一次。工具不经手你的密码，也不会替你点登录相关的任何按钮。

登录状态存在 `accounts/browser_profile/`（独立配置目录，不碰你日常那个 Chrome）。

### 想看 GA 流量还要做什么

**GSC 流量不需要任何额外配置**，现有 OAuth 授权已经覆盖（Search Analytics 就在
`webmasters` 权限下）。GA 则需要三步：

1. GCP 里启用 **Google Analytics Data API** 和 **Google Analytics Admin API**
2. 回到「账号管理」**重新授权一次**——新增了 `analytics.readonly` 权限，
   Google 要求重新走一遍授权流程，这个绕不过去
3. 到「流量数据」页点「自动匹配 GA 属性」，确认后保存

> **装了 GA 跟踪代码 ≠ 能读到数据。** 跟踪代码只负责往 Google 上报，
> 读回来是另一个方向、要单独授权。这一点容易搞混。

> GA4 只有装了跟踪代码之后的数据，没有历史回溯；免费版默认只保留 **2 个月**
> （可在 GA 后台改成 14 个月，且只对之后的数据生效）。想留更久要靠本工具的本地缓存。

### 想要更多查询配额？

查询配额按 **GCP 项目**算，不按站点算。另开一个 GCP 项目、重复上面 1~4 步、
用同一个邮箱再授权一次，每天就多 2000 次查询。工具自动在多个凭据间分派。

（申请收录的名额跟凭据无关，是 Google 按站点限制的，加凭据没用。）

## 四、界面说明

### 扫描与提交

**第一步：找出要申请的链接。两种方式，任选一种，产出完全一样。**

**方式 A · 从站点地图抓取。** 填站点地图地址（已按选中站点自动填成
`{站点}/sitemap.xml`，不对可以直接改），点「开始扫描」。工具会抓出全站 URL
并逐个查收录状态，**全部**存进链接清单（不管有没有收录）。

**方式 B · 直接粘贴链接（不用选站点）。** 把链接贴进文本框，一行一条，
也支持逗号分隔，`#` 开头的行当注释忽略。

> **可以混着粘贴不同站点的链接。** 工具会逐条查出它属于你哪个 GSC 属性——
> 手里的链接横跨几十个站点是常态，逼着你先选一个站点再粘贴是本末倒置。
> 域名属性（`sc-domain:`）和网址前缀属性都支持；一条链接同时落在两个属性里时
> （比如 `https://x.com/` 和 `https://x.com/blog/`），取**前缀更长**的那个。

> ⚠️ **GSC 把 `http://` 和 `https://` 当成两个不同的属性，`www.` 和非 `www.` 也是。**
> 网址前缀属性是**按字符串前缀**匹配的，所以 `https://example.com/` 这个属性
> 压根不覆盖 `http://example.com/page`。
> 遇到这种情况工具会**自动改写成属性的写法**，并在界面上明确告诉你改成了什么
> ——改写了你粘进来的东西就必须说出来，不能悄悄换掉。改写后如果跟已有链接重复，
> 会自动合并，不会重复占用申请名额。

判不出归属的**不会被悄悄丢掉**，而是排在表格最前面标红，并逐条说明原因：

| 情况 | 提示 | 该怎么做 |
|---|---|---|
| 协议/www 写法不同 | 自动改写，并告知「你粘的是 `http://…`，属性是 `https://…`」 | 无需处理 |
| 域名打错了 | 「你的属性里没有 `exmaple.com`，但有 `example.com`（只差 1 个字符）」 | 改对网址重新查 |
| 路径不在前缀内 | 「主机名对得上属性 `https://x.com/blog/`，但路径不在它的前缀范围内」 | 加一个覆盖该路径的属性 |
| 网站没加进 GSC | 「`xxx.com` 不在你的任何 GSC 属性里」 | 去 Search Console 添加并验证 |
| 不是合法网址 | 「这一行解析不出合法网址」 | 检查这一行 |

两种方式都用**充裕的查询配额**（2000 次/天/凭据），可以放心查。

**第二步：挑几条申请。** 下方表格默认只显示未收录的，可以切换分类：

| 分类 | 含义 |
|---|---|
| 全部 | 扫描发现的所有链接 |
| 未收录 | Google 还没收录的（默认视图，这些才需要处理） |
| 已收录 | Google 已经收录的，**置灰不可勾选** |
| 未查明 | 查询失败、状态不明的 |
| 未收录·从未申请 | 名额优先花在这些上 |
| 未收录·已申请 | 交过了，等 Google 处理 |
| 判不出归属 | 粘贴进来但对不上任何 GSC 属性的，**不可勾选**，需要你处理 |

**跨站点提交。** 选中的链接可以横跨多个站点，一次交完——GSC 的检查入口是
概览页 `?resource_id={站点}`，每条本来就要重新导航一次，所以换站点跟换网址
一样便宜，不用为每个站点重开浏览器。

> 💡 **申请名额是按站点算的，所以跨站点提交反而更划算**：粘贴 10 个站点各 1 条
> = 10 个**独立的名额桶**，比单站点交 10 条更容易成功。某个站点名额用完只会
> 跳过它自己的那几条，不影响别的站点。
>
> 点「申请收录」时会先列出**将影响哪些站点、各占几个名额、有几条会因名额不足被跳过**，
> 确认后才开始，不会闷头就交。

表格里**收录状态**和**申请记录**是分开两列的，不会混淆：
前者是 Google 的判定，后者是你通过本工具做过什么。一条从没申请过的页面
完全可能本来就是收录的。

**第三步：过几天复查。** 点「复查收录状态」，重新查询之前申请过的链接现在收录了没。
勾选了就只查勾选的，没勾就查所有"申请过但还没确认收录"的。
这个动作只花查询配额，**不消耗申请名额**，想查多少次都行。

### 链接清单

按站点汇总全部链接及收录状态，跨天保留。因为每站每天能申请的次数很少，
一次扫出的几十条得分好几天消化，所以这份清单会一直存着。
这一页也有「复查全部申请过的」入口。

### 流量数据

**先拉取，再筛选。** 两边的 Google 接口都**只支持按维度筛选、不支持按指标筛选**
——没法直接跟 Google 要"点击量大于 1000 的站点"。所以要先逐站点把总量拉下来缓存，
之后筛选就是瞬时的、阈值随便改、条件能任意组合。

**筛选能力**：指标（GSC 曝光/点击/平均排名、GA 会话/用户/浏览量/事件数）
× 比较（≥、≤、区间）× 窗口（今日 / 7 / 28 / 90 天）。
比如「GSC 曝光量 ≥ 1000」一键筛出达标的站点。

#### 「今日」窗口：两边不是同一天

> ⚠️ **GSC 没有"今天"，这是 Google 自身的延迟，代码绕不过去。** 实测确认：
> 今天是 08-21 时，GSC 最新只到 **08-18**，正好差 3 天。
> 所以「今日」窗口下两边查的是不同日期：
>
> | | 实际日期 | 说明 |
> |---|---|---|
> | GA | 今天 | 真的是今天，但今天还没过完，是**当日累计** |
> | GSC | 3 天前 | 它**最新可用的那一天**，不是今天 |
>
> 表格上方会把这两个真实日期直接写出来。**不要横向对照**——
> 同一行里 GSC 那几列反映的是三天前的搜索表现，GA 那几列是今天的。

> 「今日」的缓存**隔夜就失效**：昨天拉的数据今天打开还标着"今日"，
> 数字却是昨天的。工具会检出这种情况并在表格下方明确提示，重新拉一次即可。
> 其他窗口差一天影响不大，只有今日窗口差一天就是完全错的，所以单独处理。

> **术语对照**：GSC 的「曝光量」就是 Google 官方界面里的「展示次数」（API 字段 `impressions`），
> 指你的页面在搜索结果里被看到的次数，不是点击。
> GA 的「事件数」是 GA4 的 `eventCount`——页面浏览、滚动、外链点击都算一个事件，
> 所以它天然比会话数和浏览量大一个量级（实测某站近 7 天：会话 4534、浏览量 11354、事件 41241），
> **别拿它跟 GSC 曝光量直接比大小**，两者统计的根本不是同一件事。

**排序**：表头点一下按该列排，再点一下反转。默认方向按指标本身"好"的方向来——
平均排名、跳出率越小越好所以升序，曝光/点击/会话/浏览量/事件数越大越好所以降序。
没拉到数据的行一律沉底，不管升序降序，免得升序时一堆"—"把有数据的站点挤出视野。

> 「把还没拉取过的站点也列出来」默认不勾——否则那些站点会以 0 混进
> "零流量"的结果里，让人误判成"这站没流量"，其实是根本没查过。

> ⚠️ **流量是按窗口分别缓存的。** 在「近 7 天」拉的数据，切到「近 28 天」是看不到的
> ——那是两份独立的缓存，换窗口要重新拉一次。窗口选择器旁边会一直显示
> 「已缓存：近 7 天 79 站，GA 78 · 近 28 天 12 站」这样的说明，
> 首次进这一页也会自动选数据最全的那个窗口。没有这些提示的话，
> 默认窗口只要碰巧拉得少，看到的就是一张几乎空的表，很容易误判成功能坏了。

**单站点详情**：按天趋势图、页面表现、搜索词，以及**「已收录但零展现」**——
这一类最有指导意义：页面进了索引却没人搜到，说明这类内容没有搜索需求，
别再把稀缺的申请名额花在同类页面上。

**GA 属性自动匹配**：点一下就行，不用手抄几十个 ID。原理是读每个 GA4 属性
**数据流里绑定的真实网站地址**，拿它跟 GSC 站点比对，比按名称猜可靠得多。

**配对结果会把没配上的说清楚，而不是只报一个总数。** 这一点很重要：
配上 78 个、漏掉 1 个的时候，如果界面只淡淡写一句"配对 78 个"，
很容易被读成"全都配好了"，于是漏掉的那个站点 GA 数据一直是空白也没人管
——而空白跟"这个站真的没流量"长得一模一样。所以：

- 有任何站点没配上，配对结果页顶部是**红色横幅**，写明"这几个站的 GA 数据会一直是空白"
- 没配上的站点**排在表格最前面**并标红，不是放在末尾或脚注里
- 每一行给出**具体原因和该怎么改**，而不是"没配上"三个字：

| 原因 | 提示内容 | 该怎么做 |
|---|---|---|
| GA 那边网址填错 | 「属性 X 的数据流网址写的是 `thebasementpan.com`，跟本站点只差 1 个字符」 | 去 GA 改网址，或直接手填 ID |
| GA 里没这个属性 | 「要么还没建 GA4 属性，要么建了但数据流里没填网址」 | 去 GA 建属性/补网址 |
| 重复属性 | 「这个网址有 2 个 GA 属性，已按**哪个真的有数据**选中当前这个」 | 一般无需处理 |
| 属性没配上站点 | 单独一张表，标出**这个属性近 28 天有没有数据** | 空属性可无视；有数据的要查 |

> 同一个网址建了多个 GA4 属性时，工具会**实际去查哪个属性有数据**再决定用哪个，
> 而不是按 Google 的返回顺序取第一个。按顺序取等于随机——挑到空属性的话
> 你看到的是"这个站 GA 全是 0"，根本想不到是配错了属性。

**手动兜底**：媒体资源 ID 那一列可以直接编辑。GA 那边不方便改的时候，
自己填一个纯数字 ID 保存即可（填 `G-XXXXXXXXXX` 会被当场拦下）。
手填的映射**不会被下一次自动配对覆盖**，并且会单独标成「手动指定」，
让你知道哪几条是自己修过的。

「流量数据」页顶部也会红字列出没配 GA 属性的站点——那几列空白不是没流量，是没查过。

> ⚠️ **两个 ID 千万别混**：跟踪代码里的 `G-XXXXXXXXXX` 是**衡量 ID**，
> 只用于**发送**数据；调 API **读取**数据认的是纯数字的**媒体资源 ID**。
> 拿 G-XXXX 去调 Data API 必然失败——这是最常见的坑，工具在保存映射时会直接拦掉。

### 此刻在线（GA 实时）

「流量数据」页上方的卡片，回答"此刻站上有几个人、在看哪些页面"。
这是 GSC 完全给不了的信息，只有 GA 有。

走的是 GA4 实时报表，跟常规报表**同一个 Data API、同一个权限**，不用额外启用什么。

> 实时是「最近 30 分钟」的滚动窗口，不是「今天累计」，两个数不该互相对照。

查全部站点是并发的、并且只对**真的有人在线**的站点再去要页面明细——
串行加上给每个站都要一次明细的话，79 个站要跑几分钟，而实时数据的全部价值
就在于立刻看到。实测 78 个站点 **7.8 秒**返回。

### 账号管理

两套登录都在这一页。「凭据列表」会列出每个凭据**实际能访问的 GSC 属性**及权限级别，
当前选中的属性用 ▸ 标出——排查权限问题只看这一列就够了。

### 历史统计

累计数据、链接概览、最近 14 天趋势，以及**两种提交方式的效果对比**
（`webauto` 网页自动化 vs `indexing_api` 已移除的旧通道），方便你自己判断。

查询相关和申请相关的参数分开两组，避免混淆。

## 五、几条不能碰的红线

这几条写在代码里，不是靠自觉：

1. **遇到验证码或安全验证，整批任务立刻停止**，绝不尝试识别或绕过。
2. **每站每日申请上限**（默认 8 次，可调）。

   > **Google 那边真实的上限是多少并不确定。** 实测观察到在某个站点上成功 1 次后，
   > 同站点换新文章立刻返回"超出了配额"——**能确定的是配额按整个站点算，不是按单篇网址**。
   > 但不能由此推断"每天只有 1 次"，因为无法排除站点所有者当天已手动提交过若干次。
   > 实际使用以工具返回的"超出了配额"为准，撞上了就是当天到顶了。

3. **只有真正提交成功才占用本地名额。** 网络中断、找不到按钮等根本没交出去的情况
   会把名额退回来——名额本来就稀缺，一次抖动白吃掉一个的话当天就没法用了。
4. **点击之间有随机间隔**（默认 4~9 秒），不做高频连续操作。

## 八、常见问题

**Q：为什么要两套登录？不能只用一个吗？**
不能。查收录用的是 Google 官方开放的 API，走 OAuth；而「请求编入索引」Google
从没开放过 API，只能自动操作网页，需要一份真实的浏览器登录。两件事走的是两套系统。

**Q：提示 `User does not have sufficient permission for site 'https://xxx/'`**
凭据对这个属性没权限，或级别不够。注意 GSC 权限是**按属性逐个授予**的，而且
「域名属性」`sc-domain:example.com` 和「网址前缀属性」`https://example.com/`
在 GSC 里是**两个互不相通的属性**。打开「账号管理」页看「可见的 GSC 属性」一列，
对不上就是没授权到这个属性。

**Q：浏览器登录时提示"此浏览器或应用可能不安全"**
说明没用上你本机真实的 Chrome。检查 Chrome 是否装在常规位置
（`C:\Program Files\Google\Chrome\`）。

**Q：报错 `Target page, context or browser has been closed`**
有上次没退干净的浏览器进程占着工具的配置目录。Windows 上 Chrome 的"同一配置目录
只允许一个实例"是靠进程实现的，而 Chrome 启动时常会自我重启换进程号，
导致自动化框架收尾时杀不掉它。工具现在会在每次启动浏览器前后自动清理，
正常不该再遇到。万一碰上，任务管理器里结束命令行含项目路径的 chrome.exe 即可
（不影响你日常用的 Chrome，两者配置目录不同）。

**Q：申请收录成功了，但去 GSC 网页看还是显示「请求编入索引」，没有"已申请"状态？**
正常现象。GSC 网页上这个按钮**没有"已申请过"的状态区分**，不管你之前交过没有，
它永远显示成可点击的样子。真正反映进展的是按钮上方的"网址状态"
（网址未收录 / 已抓取未编入索引 / 已编入索引），这个本身更新就要几小时到几周。
想确认工具有没有交上去，看「历史统计」的日志。

**Q：配额什么时候重置？**
查询配额按太平洋时间零点重置（约北京时间下午 3~4 点，受夏令时影响）。
申请名额的重置时间 Google 没公开，工具本地按同样口径记账。

**Q：为什么筛选不能直接让 Google 帮我筛？**
GSC 和 GA 的接口都只支持按**维度**筛（页面、查询词、国家、设备），
不支持按**指标**筛。所以必须先逐站点拉总量、缓存到本地，再在本地筛。
好处是数据缓存后筛选瞬时、阈值随便改。

**Q：明明拉过数据，表格却是空的/只有几个站**
流量按**窗口**分别缓存，在「近 7 天」拉的数据切到「近 28 天」看不到。
看窗口选择器旁边的「已缓存：…」那行，它会告诉你数据在哪个窗口、各有多少个站。
空表也会直接说明是哪种情况，并给出可以一键跳过去的窗口按钮。

**Q：配对结果说"1 个站点没找到对应 GA 属性"，要怎么办？**
看那一行写的原因，它会告诉你去哪儿改。最常见的一种是 GA 后台某条数据流的
网址填错了一两个字母，工具会直接指出"写的是 X，跟本站点只差 1 个字符"。
去 GA 改对再重新配对，或者直接在那一行手填媒体资源 ID 保存。
**不处理的后果是这个站点的 GA 数据一直空白**，而且空白看起来跟"没流量"一样。

**Q：配对结果说"N 个 GA 属性没配上站点"，要处理吗？**
看下方那张表里「近 28 天」这一列。显示"空"的是重复创建、没装跟踪代码的属性，
可以放心无视（想让提示消失就去 GA 删掉）。**显示有会话数的要留意**——
说明这个属性在收数据但没配上任何站点，通常是网址填错了，
或者这个网站还没加进 Search Console。

**Q：GA 那几列一直是空的**
三种可能，按顺序排查：① 当前凭据没有 `analytics.readonly` 权限（需重新授权）；
② GCP 里没启用 GA Data API / Admin API；③ 还没配站点与 GA4 属性的对应关系
（到「流量数据」页点「自动匹配 GA 属性」）。「流量数据」页顶部的提示会直接说是哪一种。

**Q：GSC 流量为什么查不到今天的数据？**
Google 自身有 2~3 天延迟，这不是工具的问题（实测：今天 08-21，GSC 最新只到 08-18）。
所以窗口末端会自动往前推几天，免得把还没就绪的日期算进来、误判成"这几天零流量"。
想看真正的"今天"只能看 GA 那几列，或者用「此刻在线」卡片。

**Q：一定要先扫站点地图吗？想直接交手上的几条链接**
不用。「扫描与提交」页第一步有「方式 B · 直接粘贴链接」，贴进去就行，
**也不用先选站点**——工具会逐条判定每条链接属于你哪个 GSC 属性。
命令行是 `gsc.py inspect --auto --file urls.txt`。

**Q：粘贴的链接里有几条说"判不出归属"**
表格最前面那几条红的就是，每条都写了原因。最常见的是域名打错一个字母，
工具会直接指出"你的属性里有 XXX，只差 N 个字符"。另一种是这个网站还没加进
Search Console——加进去并验证之后才能申请收录。
**这些链接不会被提交**，所以不处理就等于漏掉了。

**Q：交了为什么还没收录？**
「请求编入索引」只是让 Google **优先排队抓取**，不保证一定收录。
最终收不收录取决于页面质量、站点权重、内部链接等因素。
建议配合站点地图提交一起用，并用扫描功能持续观察实际变化。

## 九、技术栈

后端 Python（FastAPI + uvicorn + google-auth + requests + playwright），
前端是零依赖的单文件 HTML/CSS/JS，本地数据用 SQLite。
除 Google 官方 API 和 GSC 网页本身以外，不向任何第三方服务器发送数据。
